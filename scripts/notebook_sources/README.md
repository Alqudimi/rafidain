# مصادر بناء دفترَي التدريب

الدفتران في جذر المستودع مبنيان من هذه المصادر — استخدمها لإعادة التوليد أو التعديل
مستقبلاً بدل تحرير ملف `.ipynb` مباشرة.

## دفتر RunPod — `runpod_cells/`

33 ملفاً مرقّماً (`00`–`32`)، ملف واحد لكل خلية بالترتيب نفسه الذي يظهر في
`rafidain_runpod_training.ipynb`: ملفات `NN_md_*.md` خلايا توثيق، و`NN_code_*.py`
خلايا كود. فحص صحة السكربتات المضمّنة داخل الخلايا:

```bash
python3 check_embedded.py
```

## دفتر Google Colab (نسخة 2) — `colab_cells_a/b/c.py`

ثلاث وحدات تصف الخلايا كسلاسل نصية (`CELLS_A` + `CELLS_B` + `CELLS_C`)، يجمعها
منشئ الدفتر ويتحقق منه تحققاً كاملاً:

```bash
python3 build_colab_nb.py        # يعيد توليد rafidain_colab_training.ipynb في جذر المستودع
```

### فلسفة النسخة 2 — «لا عمليات خلفية، استيراد فقط»

النسخة الأولى كانت تُطلق التدريب كعملية خلفية مستقلة عن النواة (start_new_session)،
مع مراقب نسخ دائم إلى Drive وحلقة انتظار لساعات — وهي أنماط تصنفها سياسة الطبقة
المجانية في Colab «استخداماً غير مسموح» فتقطع الجلسة فجأة (Runtime disconnected).
النسخة 2 أزالتها كلها:

| النمط القديم | البديل في النسخة 2 |
|---|---|
| تدريب بعملية خلفية مستقلة + ملف PID | التدريب في **مقدمة الخلية 12**: استيراد `train.py` من seed-vc وإنشاء `Trainer` واستدعاء `.train()` مباشرة |
| مراقب نسخ دائم إلى Drive (حلقة sleep) | غلاف حول `torch.save` داخل عملية التدريب نفسها ينسخ كل نقطة إلى Drive لحظة حفظها (بلا أي خيط/عملية إضافية) |
| خلية «انتظار الاكتمال» (حلقة 11 ساعة) | حُذفت — النواة مشغولة بعمل حقيقي أصلاً أثناء التدريب |
| خلايا البيانات تجلب من 5 مصادر ثم تقطّع وترمّز (ساعات) | خلية واحدة تنزّل **أرشيفاً جاهزاً** `rafidain_current_sources_ready.tar.gz` (4.89GB، 56,856 مقطع Opus / 387.8 ساعة) وتفكّه مباشرة — بلا إعادة تنزيل من المصادر ولا إعادة معالجة |
| استدعاء سكربتات بأوامر سطرية (`venv/bin/python iraqi_pipeline.py small ...`) | كل منطق المشروع يُستدعى **بالاستيراد**: `iraqi_pipeline` (prefetch/export)، `train`/`inference` من seed-vc (تدريب/تحقق)، `finetune.checkpoint_sync` (استعادة النقاط) |
| تنزيل الأرشيف من الصفر كل جلسة | تنزيل **قابل للاستئناف** (`curl -C -`) + تحقق الحجم الدقيق بالبايت قبل الفك + بصمة `.ready_archive_ok` تمنع أي إعادة + نسخة Drive تُستعمل إن وُجدت |

الفحوص التي يجريها المنشئ آلياً: صحة JSON وnbformat، صحة نحو كل خلية كود، تسلسل
الترقيم العربية ١–١٨، ثوابت خلية الإعداد (مسارات الأرشيف وروابطه)، **منع أنماط
الخلفية نهائياً** (فحص start_new_session/setsid/nohup/PID/while-True)، وجود
تنزيل-الاستئناف وتحقق الحجم والبصمة، واستيراد المدرب والاستدلال كوحدات.

## اختبارات الدفتر — ثلاث طبقات

```bash
python3 test_notebook_logic.py     # 28 فحصاً: الأرشيف الحقيقي، الفهرس، الاستعادة، مرآة Drive، بلا خلفية
python3 test_train_driver_e2e.py   # 8 فحوص: تشغيل برنامج التدريب المضمّن فعلياً ضد seed-vc وهمي
python3 test_kernel_sim.py         # 24 فحصاً: تنفيذ الخلايا القابلة للتشغيل بالترتيب في نواة محاكاة
```

> الخلايا (ليست وحدات مستقلة)، ويراقَب صحتها بالفاحصات أعلاه. أثناء تحرير
> `colab_cells_*.py` احترس من الفواصل الثلاثية `'''` داخل أجسام الخلايا — تستبدل
> بـ `chr(39)*3` (متغير `Q`) أو `chr(34)*3` (متغير `TQ`) كما في الخلايا الجاهزة.
